2. 原則

#原則状態
P1Emacsからはキーの意味を引き継ぐ。文節は「文字列の中の単位」、候補は「縦に並んだリスト」とみなす。 そのため、変換中は C-f/C-b で文節を移動し、C-n/C-p で候補を切り替える。決定
P2同じキーは、どの状態でも似た意味を持つようにする（例: C-g はどの状態でも「1段階戻る」）。決定
P3よく使う操作には、修飾キー1つ（Ctrl）で押せるキーを割り当てる。Ctrl+Shift は押すのに一手間かかるため、主に次の2つの用途で使う。(a) 同じ操作をする別のキー（例: C-S-b/C-S-f）。(b) Ctrlだけでは対になるキーが取れない操作（例: M-v の代わりの C-S-v）や、あまり使わない操作（例: 再変換の C-S-Space）の主なキー。 Meta/Alt/Option は使わない（macOSのOptionは記号入力に、WindowsのAltはメニューに使われるため）。決定
当初の案「Ctrl+Shiftは範囲の伸縮に使う」は、実機で C-S-f が C-o より一手間かかるとわかったので改めた。さらに (b) を追加した（2026-11-13）
P4IMEが処理するキーは最小限にする。入力文字なしの状態ではCtrlキーを定義せず、アプリに渡す。 例外は、処理することがなければアプリに渡されるコマンドに限る（→ 4.1）。決定
P5kotoeri.tsv に差分を追記するのではなく、キーマップ全体を自分で書く。追記方式では、既定の不要な行を消せないため。決定
P6C-i と Tab、C-m と Enter、C-h と Backspace のように、OSによって区別できない可能性のある組は、同じ意味にしておく。決定

3. 状態をまたぐ遷移: 進む・抜ける・戻る

状態は4つ（IMEオフ / 入力文字なし / 読み入力中 / 変換中）。Emacs風の遷移は次の3方向にまとめる。

方向状況挙動キー状態
進む 読み入力中Space: 変換を始める / C-n Tab C-i: 予測変換に入る（どちらも → 変換中）Space C-n Tab C-i決定
Space は文節に区切って変換し、C-n は予測変換の候補一覧に入る（2026-11-13に試して決定）。Tab と C-i も予測変換にする（P6）。変換中の Tab と C-i は「文節を縮める」なので、Tabの意味は状態によって変わる
入力文字なし文字キーで読みの入力を始める（→ 読み入力中）文字キー決定
抜ける 読み入力中・変換中確定する（→ 入力文字なし）C-m Enter案
戻る 変換中変換を取り消して読みに戻る（→ 読み入力中）C-g ESC C-h Backspace案
読み入力中読みを破棄する（→ 入力文字なし）C-g ESC案
読み入力中最後の1文字を消すと、入力文字なしに戻るC-h C-d案

変換中に C-g を2回押すと、読みの破棄まで戻る。Emacsで C-g を連打したときの感覚と同じになる。変換中の C-g で読み入力中に戻ること、読み入力中の C-g で読みが消えることは、実機で確認した（2026-11-13）。

4.4 候補ウィンドウが出ている間（Suggestion / Prediction）

この2つは親の状態（読み入力中 / 変換中）の定義を引き継ぐ。差分は持たせない方針（案）。 読み入力中にも C-n を定義すれば、サジェスト候補が出ているかどうかで C-n の挙動が変わることはなくなる。

4.5 文字幅（全角 / 半角）

状況挙動設定状態
IMEオン（ひらがな入力）で数字 0〜9 を打った読み入力中も変換後も半角にするmozc/config.base.textproto の character_form_rules で、"0" のグループを HALF_WIDTH にする案
ルールを1つでも書くとMozcの既定のルールが使われなくなるため、ほかのグループは既定と同じ値で書き並べている。実機ではまだ確かめていない
数字の後に「.」「,」を打った（例: 3.14、1,000）半角にする（全角の「．」「，」が混ざらないようにする）".," のグループを HALF_WIDTH にする。ふつうに打つ「。」「、」は別のグループ（"。、"）なので全角のまま案
既定の設定では「3．14」「1，000」と混ざることを実機で確認した（2026-11-13）
IMEオン（入力文字なし）で Space を打った全角の空白（Mozcの既定のまま）。半角の空白は S-Spacespace_character_form は書かない（既定）。Precomposition Shift Space InsertAlternateSpace（設定と逆の幅の空白を入れる）決定
一度は「既定は半角、S-Space で全角」にしたが、Shiftを付けると全角になるキーはほかに無いので戻した（2026-11-13）。このキーマップでのShiftは「逆・もう一方」を表す（S-Space・S-Tab で前の候補、C-S-v で前のページ、S-←/S-→ で範囲）。 「全角の空白を打ってから C-l で半角にする」はできない（C19）
数字の後に「-」を打った（例: 2026-11-13）、IMEオンで + = * < > を打ったASCIIの半角にする"<>=+-/*" のグループを HALF_WIDTH にする決定
既定では、数字の後の「-」は U+2212 MINUS SIGN になる（C14）
数字の後以外で「-」をASCIIで入れたい「-」を打つと「ー」になるので、続けて C-l（半角英数で表示）を押して「-」にする。- キーのまま「-」を出す設定にはしない（長音の「ー」が打てなくなるため）キーマップのまま（C-l = DisplayAsHalfAlphanumeric）案
半角英数は、表示中の文字ではなく打ったキーそのもの（raw）から作られる（composer/transliterators.cc の HalfAsciiTransliterator）。そのため読み全体が対象になり、「らーめん」で押すと「ra-men」になる。実機ではまだ確かめていない
英字・記号を打ったMozcの既定のまま（読み入力中は全角、変換後は前回選んだ幅）同上未定

7. 衝突・懸念のメモ

決めた割り当てについて、ほかのキーとの衝突や気になる点を書き留める。確認作業は TODO.html に載せる。

#対象衝突・懸念今の扱い
C1入力文字なしの C-g（確定の取り消し） 確定した直後に限って、アプリの C-g ではなく確定の取り消しになる。たとえばEmacsで確定直後に keyboard-quit のつもりで押すと、確定が取り消される。 確定の取り消しは、取り消せる状態のあいだはキーを消費する。アプリが直前の文字の削除に対応していない場合（macOSでは選択範囲を返さないアプリ）は、何も起きずにキーだけが消える可能性がある 決定 Enterで確定した後は効かなかった（変換中に一部だけ確定した後は戻った）。確定直後の C-g がアプリに渡らなくなる害のほうが大きいので、入力文字なしの状態の C-g と C-Backspace から確定の取り消しを外した（2026-11-13）
C2C-S-Space（再変換） 再変換は、選択している文字列がなくてもIMEがキーを消費する。そのため、IMEオンの間はアプリの C-S-Space が使えなくなる（例: Windows/LinuxのVS Codeのパラメーターヒント）。macOSでは、選択がないと確定の取り消しを試す IMEオフでは定義しない。衝突するアプリが見つかったら考え直す
C3Tab の意味が状態によって変わる 読み入力中のTabは予測変換、変換中のTabは「文節を縮める」（P6で C-i とそろえたため）。kotoeri.tsv では、変換中のTabは次の候補だった。 予測候補の選択中（Prediction）も変換中の定義を引き継ぐので、Tabは「縮める」になる。予測候補の選択中に縮めると、変換を始める前の状態に戻ったように見えた（実機で確認）。Mozcのソース（engine/engine_converter.cc の ResizeSegmentWidth）では、予測候補の選択中は文節の伸縮をせず、候補ウィンドウを閉じるだけになっている 試行中。予測候補の選択中のTabは実害が少ないので、ひとまずこのまま
C4区別できない可能性のあるキーの組（C-i/Tab、C-m/Enter、C-h/Backspace） macOSでは区別できる。Fcitx5（Linux / WSLg）とWindowsでは確かめていない。P6で同じ意味にそろえているので、区別できなくても挙動は変わらない想定 未確認
C5Ctrl+Shift+文字キー（C-S-b/f/v、C-S-Space） macOSでは C-S-b/f がMozcに届く（E2Eで確認済み）。Fcitx5・WSLg・Windowsでは確かめていない。届かない環境があれば、その環境では C-i/C-o などCtrlだけのキーで代わりができるかが重要になる 未確認
C6読み入力中・変換中の C-k Emacsの行末まで削除に当たるコマンドはMozcにない。C-q に移したので、C-k は何も割り当てていない（押してもIMEに捨てられる） そのまま
C7C-l を半角英数にした SKKの l に合わせた。kotoeriでは全角英数だった。全角英数で表示するキーは F9 だけになる 試行中
C8C-; C-: C-' キーボードの配列によって押し方が変わる（US配列では : にShiftが要る）。ことえり由来で残しているだけ そのまま
C9読み入力中の C-n（予測変換） 予測候補がまったくないときにどう動くか確かめようとしたが、そういう読みが見つからなかった。ソース（session.cc の PredictAndConvert）では、予測できなければ読み入力中のまま何も変わらない 気にしなくてよい
C10文字幅のルール（4.5） ルールを1つでも書くと、Mozcの既定のルールは使われない。将来Mozcの既定が変わっても、こちらには反映されない。英字・記号の LAST_FORM は学習データ（cform.db）を使うので、学習を消すと挙動が変わる 既定と同じ値を書き並べている
C11config1.db の上書き Google日本語入力の設定画面で「OK」を押すと、手で置いた config1.db が上書きされ、このキーマップが消える 設定画面を使わない運用にする（未定）
C12Emacs自身の上で使うとき 入力文字なしの状態ではキーがEmacsに渡るので、通常の編集には影響しない（C1で確定の取り消しを外したので、C-g も常にEmacsに渡る） 問題なし
C13数字を半角にした（4.5）と C-j / C-q C-j（ひらがなで表示）と C-q（全角カタカナで表示）では、数字は全角にならず半角のまま（2026-11-13に実機で確認）。 Mozcのソース（composer/transliterators.cc）を読むと、この2つはいったん全角にした後で、4.5 の文字幅ルールを当て直しているため。文字幅ルールを使わず全角にするのは「全角英数で表示」（F9）だけ。変換候補の一覧にも全角の数字は出る 仕様どおり。全角の数字をよく使うなら、全角英数で表示するキーを追加する（P3(b)により、例: C-S-l）
C14数字に続く . , -（4.5） 数字の後の「。」「、」「ー」は、読み入力中に「．」「，」「−」へ置き換えられる。既定の幅のルールのままだと、「3．14」「1，000」のように半角と全角が混ざる（実機で確認）。 「-」は「09−2−22」のように U+2212 MINUS SIGN になる（実機で確認）。見た目は半角に近いが、ASCIIの「-」ではない。Mozcでは U+2212 が「-」の全角形として扱われていて、"<>=+-/*" のグループ（読み入力中は全角）のルールが当たっているため ".," を半角にした（4.5）。「3.14」「1,000」は混ざらなくなった（実機で確認）。「-」も "<>=+-/*" のグループを半角にしてASCIIにした（+ = * なども半角になる）。実機ではまだ確かめていない
C15C-q の意味 Emacsの C-q は quoted-insert（次の1文字をそのまま入力する）。この意味で「C-q . で半角の . を入れる」ことはできない。Mozcのキーマップは1回のキー入力にしか割り当てられず、次の文字をそのまま入れるコマンドもないため。今は C-q を全角カタカナにしているので、Emacsの意味とは食い違う（P1） SKKに寄せることを優先して、そのまま
C16範囲選択して Space で再変換したい 今は C-S-Space で再変換できる（実機で確認）。Space で再変換するのはキーマップでは実現できない。IMEの変換サーバーはアプリの選択範囲を知らないので、「選択があるときだけ再変換、無いときは空白」という分岐ができない。 入力文字なしの Space を再変換にすると、選択が無いときに空白が入らなくなる（再変換は常にキーを消費し、macOSでは代わりに確定の取り消しを試すだけ）。今の Space は半角の空白をアプリに渡すので、選択範囲が空白で置き換わって消える 決定 C-S-Space のまま。どうしても必要なら、OSS版のMozcのmacOSクライアント（mozc_imk_input_controller.mm）を改造し、選択があるときだけ Space を再変換にする方法がある
C17範囲選択中の C-g で選択を解除したい 選択の解除はIMEではなくアプリ側の操作（Q11）。入力文字なしの C-g は、取り消せる確定が無ければアプリに渡る。ただし、確定の直後に範囲を選択して C-g を押すと、選択の解除ではなく確定の取り消しになる（C1）。 macOSのCocoaアプリでは DefaultKeyBinding.dict で C-g にアクションを割り当てられるが、選択の解除だけをする標準のアクションは無さそう。たとえば moveRight: を割り当てると、選択があれば末尾で解除されるが、選択が無いときは1文字進んでしまう 決定 IMEの設定では無理なので諦める（2026-11-13）。参考までに、残っている手段: macOSなら Hammerspoon などで、C-g を押したときにアクセシビリティAPIで選択範囲（AXSelectedTextRange）を調べ、選択があれば → を送って解除し、無ければ C-g をそのまま渡す。IMEの外の仕組みで、OSごとに別の実装になる
C18undo / redo のキー IMEで指定できるのは「確定の取り消し」（Undo。入力文字なしでは C-g）だけ。Mozcに redo のコマンドは無い。 確定した後の文章の undo / redo はアプリ側の操作（Q11）。macOSでは Cmd-z / Cmd-Shift-z が標準。Emacs風に C-/ などにしたい場合は、Cocoaアプリなら DefaultKeyBinding.dict で undo: / redo: を割り当てる（効くかは要確認）。 入力文字なしの C-/ はIMEに定義していないので、アプリに渡る IMEの外の作業としてTODOに載せた
C19空白を「既定は全角、C-l で半角」にしたい 実現できない。入力文字なしの状態で打った空白は、全角なら読み入力中に入らず、その場で確定する（session.cc の InsertCharacter が CommitCompositionDirectly を呼ぶ）。半角ならアプリにそのまま渡る。どちらも C-l を当てる対象が残らない。 Space を「読みの入力を始める文字」として扱わせる設定にすると、続けて打つ読みと空白がひとまとまりになり、2回目の Space で変換が始まってしまう 決定 Space と S-Space で幅を分ける（Space が全角、S-Space が半角）
